Selected work

Architecture that enforces itself

S2B · ArchUnit, authoring-time hooks, 107 reference documents

Problem
One architect cannot review 59 people's code. Standards that live only in documents are found to be broken in review — when the cost of fixing them is already high.
Approach
Move the control point to the moment code is written. I wrote the ArchUnit ArchitectureTest suites for all seven services (45–49 rules each) so layering, package, and naming rules fail as tests, and deployed hooks that surface the governing standard the instant a file is edited. Shared foundation code stays under change control and is updated centrally.
Result
Architectural consistency stops depending on any individual's diligence — including mine.

Harness engineering — holding AI coding agents to the standard

S2B · four layers, 46 predefined scenarios, model-agnostic entry points · full case study →

Problem
An SI program redefines its standards from scratch every time, then leans on senior reviewers to enforce them — a bottleneck that never scales across vendors and skill levels. AI made this worse before it made it better: an agent forgets everything between sessions, output tracks whoever wrote the prompt, and a documented rule the agent never reads is not a rule.
Approach
A harness in four layers with explicit load boundaries. A routing entry point recognises what arrived — a table name, an HTML file, a spec document, plain language. Always-resident rules carry structure and naming. 46 predefined scenarios cover the program's development cases step by step and load only when called; a reference library of verified examples is pulled in selectively; role-isolated agents execute. One table name yields five CRUD APIs with JUnit tests and REST Docs.
Why it holds
Entry points are separated, so the same harness runs on Claude outside the client network and on Qwen3 inside the air-gapped one — it outlives any single model or vendor. Known failures accumulate in a reference file, so the same AI mistake does not recur next session. And the whole thing ports to the next engagement by copying one folder and renaming the domain.
Result
A company-wide AI Innovation Award, and an invitation to present the framework at the Shinsegae Group IT innovation forum and to the CEO as a group-wide standard. I also built the measurement system that backs the claim — PM-approved WBS as the baseline, effort collected from hooks rather than self-reported, artifacts attributed to the commit that introduced them, savings capped at 80% per item — which puts 79.7% effort reduction (82 → 16.7 man-days) behind it. The architect's job moves from writing standards and defending them in review to controlling them in the system.

From rollback APIs to a choreographed Saga

Starbucks Korea · Kafka, compensating transactions

Problem
Cross-service transactions were held together by rollback APIs, making every service responsible for its callees' transactions. A single failure cascaded into depth-wide retries and surfaced only as a read timeout, while a partial rollback left the system inconsistent with no traceable cause.
Approach
Each service publishes a completion event the next one subscribes to, and a failure event that upstream services subscribe to in order to run compensating transactions.
Result
Services decoupled, consistency preserved on account withdrawal, and root-cause analysis reduced to reading the sequence of published events.

A message catalog operators can actually change

Starbucks Korea · event-driven cache invalidation across services

Problem
Customer-facing copy was scattered across domains. Changing one line needed a developer, and any domain caching it needed separate handling.
Approach
An administration screen for operators, message definitions consolidated into one owning service, and each domain subscribing only to the message IDs it actually uses — evicting just that message from its own Redis cache on an update event, with a dead-letter consumer and critical-log alerting behind it.
Result
Copy changes without a deployment or a manual cache purge, while each domain still reads messages locally instead of calling the owning service on every request.

Two performance problems worth the dive

Starbucks Korea · data modeling and batch design

Result
3–10 s → 73–180 ms. Payment history shared a table with vehicle entry/exit records and had neither a primary key nor an index. Splitting the tables and adding a composite index on customer and vehicle removed a platform-wide slowdown.
Result
8 h → 2 h. A notification batch ran push and KakaoTalk delivery in series, scanned every vehicle, and decrypted license plates before filtering them. Parallel jobs, an index, reordered decryption — and send time became an Airflow parameter, so operations changes delivery time without a deployment.

S2B — 전국 학교가 쓰는 전자조달 플랫폼 재구축

Application Architect · 2025.11 – 현재 · 신세계아이앤씨 / 한국교직원공제회

전국의 모든 초·중·고와 교육기관이 S2B를 통해 물품을 구매합니다. 이 시스템을 18개월에 걸쳐 프라이빗 클라우드 기반으로 전면 재구축하는 사업이고, 8개 저장소에 59명이 다벤더로 참여합니다.

저는 7개 마이크로서비스의 애플리케이션 아키텍처를 담당합니다. 계층 구조, 업무 패키지 체계, BFF 조회 패턴, 예외 처리 규약, 그리고 서비스 간·대외기관 연계 방식을 정의합니다. 이 사업의 제안 단계에서 목표 아키텍처를 설계해 수주까지 이어졌기 때문에, 고객에게 약속한 아키텍처를 제가 그대로 구현하고 있습니다.

주요 작업

스스로 지켜지는 아키텍처

S2B · ArchUnit, 작성 시점 Hook, 표준 문서 107건

문제
아키텍트 한 명이 59명의 코드를 리뷰할 수는 없습니다. 문서로만 존재하는 표준은 리뷰 시점에야 위반이 발견되고, 그때는 이미 수정 비용이 큽니다.
접근
통제 지점을 코드가 작성되는 순간으로 옮겼습니다. 7개 서비스 전체의 ArchUnit ArchitectureTest를 직접 작성해(서비스당 45~49개 규칙) 계층 의존·패키지·명명 규칙이 테스트로 실패하게 만들고, 파일을 편집하는 즉시 해당 표준을 제시하는 Hook을 배포했습니다. 공통 기반 코드는 변경 통제 대상으로 두고 중앙에서 일괄 적용합니다.
결과
아키텍처 일관성이 개인의 숙련도나 주의력에 의존하지 않게 되었습니다. 저 자신을 포함해서요.

하네스 엔지니어링 — AI가 표준을 지키게 만드는 일

S2B · 4계층 구조, 46개 시나리오 사전 정의, 도구 독립적 진입점 · 상세 보기 →

문제
SI 사업은 매번 표준을 처음부터 다시 정의하고, 결국 시니어의 PR 검증에 의존합니다. 인력 수준 편차와 협력사별 해석 차이를 사람이 감당하는 구조는 확장되지 않습니다. AI는 이 문제를 먼저 키웠습니다. 세션이 바뀌면 기억을 잃고, 결과는 프롬프트를 쓴 사람 실력을 따라가며, 읽히지 않는 규칙은 규칙이 아닙니다.
접근
로드 경계를 명확히 나눈 4계층 하네스를 만들었습니다. 진입점이 입력 유형을 판별하고(테이블명·HTML·스펙 문서·자연어), 상주 규칙이 구조와 명명을 담당합니다. 46개 시나리오가 사업의 개발 케이스를 단계별로 정의해 호출 시에만 로드되고, 검증된 예시는 필요한 것만 선택적으로 참조하며, 역할별로 격리된 에이전트가 실행합니다. 테이블명 한 단어를 넣으면 CRUD API 5개와 JUnit 테스트, REST Docs 명세가 나옵니다.
버티는 이유
진입점을 분리해서 외부망 Claude와 내부망 Qwen3에서 같은 하네스가 동작합니다. 특정 모델이나 벤더보다 오래 살아남는다는 뜻입니다. 발생한 오류는 Reference 파일에 누적되어 다음 세션에서 같은 실수가 반복되지 않습니다. 그리고 폴더 하나를 복사해 도메인명만 바꾸면 다음 사업에서 그대로 작동합니다.
결과
전사 AI 혁신상 수상. 신세계그룹 IT 혁신 포럼과 CEO 대상 발표에 그룹 표준으로 제안되었습니다. 주장의 근거가 될 측정 체계도 함께 만들었습니다. PM 승인 WBS를 기준선으로 두고, 공수는 자기신고가 아니라 Hook으로 수집하고, 산출물은 그것을 처음 만든 커밋에 귀속시키고, 인정 절감률에는 건당 80% 상한을 두어 공수 79.7% 절감(82MD → 16.7MD)을 확인했습니다. AA의 일이 표준을 문서로 쓰고 리뷰에서 설득하는 것에서, 시스템으로 통제하는 것으로 옮겨갔습니다.

Rollback API에서 코레오그래피 Saga로

스타벅스 코리아 · Kafka, 보상 트랜잭션

문제
서비스 간 트랜잭션이 rollback API로 묶여 있어, 각 서비스가 자신이 호출하는 서비스의 트랜잭션까지 책임지는 구조였습니다. 한 곳의 장애가 호출 depth만큼 retry로 연쇄되어 결국 read timeout으로만 드러났고, 부분 롤백만 수행되면 일관성이 깨진 채 원인을 추적할 수 없었습니다.
접근
각 서비스가 완료 이벤트를 발행하면 다음 서비스가 구독해 이어받고, 장애 시에는 장애 이벤트를 발행해 상위 서비스가 보상 트랜잭션을 수행하도록 재설계했습니다.
결과
서비스 간 결합이 사라지고 회원 탈퇴의 데이터 일관성이 유지되었으며, 원인 파악이 발행된 이벤트 순서를 읽는 일로 단순해졌습니다.

운영자가 직접 바꿀 수 있는 메시지 체계

스타벅스 코리아 · 이벤트 기반 도메인별 캐시 무효화

문제
고객에게 노출되는 문구가 각 도메인에 흩어져 있었습니다. 한 줄을 바꾸는 데 개발자가 필요했고, 캐시를 쓰는 도메인은 반영을 위해 별도 조치가 필요했습니다.
접근
운영자용 관리 화면을 만들고 메시지 정의를 단일 소유 서비스로 모았습니다. 각 도메인은 자신이 실제로 쓰는 메시지 번호만 구독하고, 변경 이벤트를 받으면 해당 메시지만 자기 Redis 캐시에서 무효화합니다. 뒤에는 DLQ 컨슈머와 크리티컬 로그 알림을 두었습니다.
결과
배포나 수동 캐시 삭제 없이 문구를 바꿀 수 있게 되었고, 각 도메인은 여전히 매 요청마다 소유 서비스를 호출하지 않고 로컬 캐시로 처리합니다.
